# Ela Maayan content harness

Git is authoritative for skills and knowledge. Notion mirrors it only under the Ela Maayan Hub. Drive stores media and production files. Start with `docs/README.md` and `references/sources.json`.

## Start

For social requests, use `el-hamaayan-content-router` as the entry procedure. Load `registry/content-types.json`, `docs/taxonomy/README.md` and `docs/architecture/modular-content-system.md`. Infer format, recipe, purpose, audience stage and intended outcome independently. For a new or unclear concept use `el-hamaayan-social-brainstorm`; for an approved revision inherit the existing record and apply the change. The classifier is an explainable lexical aid, not semantic authority.

1. Read relevant local knowledge, decisions and the latest Git content handoff. Check the existing operational Notion content-bank item for publishing status and asset links. Do not require Notion to read knowledge present in the checkout.
2. Match `skills/*/SKILL.md` by frontmatter name and read only relevant procedures. Their reference files resolve to local canonical documents.
3. Treat archived evidence as dated, not current platform behavior or live analytics. Refresh time-sensitive facts when needed.
4. Fetch real media through stable Drive IDs/URLs into ignored temporary space. Bundled preview images and raw CSVs mentioned by imported skills are external. Run scripts only with real temporary input paths.
5. Follow the user's brief and accepted Git decisions when they refine imported defaults. CTAs are optional; story, humor, friendship or beauty can be complete outcomes.

## Produce and review

- Applying this system to existing content means understanding, classifying and preserving it. Preserve the original font files, actual weights, typography, composition and renderer unless a redesign or specific visual change is requested. Read [the preservation lesson](docs/learnings/preserve-established-design.md). Do not substitute a similar font or rebuild a layout solely to demonstrate the system.

- Preserve approved wording exactly; line breaks may change for layout. Record requested wording changes and rationale.
- Use real photos, screenshots and evidence; do not invent product behavior, quotes or metrics.
- Inspect carousel slides 1 and 2 independently and in sequence, the full payoff, Hebrew RTL and phone readability. Read the current brand direction before refining it.
- Separate owner preference, observation, platform statement, design principle and experiment. Retain superseded rationale.
- Apply a small approved revision without reopening the whole concept.

## Save

1. Save knowledge in `docs/`, decisions in `docs/decisions/`, content records and handoffs in `docs/content/<format>/<recipe-or-candidate>/<slug>/`, and reusable learning in `docs/learnings/`. Use the templates. Store text and stable asset references in Git.
2. Save authorized production files/exports to the established Drive destination with a version name. Record source/output IDs and versions in the Git content record.
3. Commit knowledge and procedure changes first. Inspect staged contents; exclude media, downloads, raw datasets, account exports, credentials and signed URLs. Knowledge and analysis belong in Git; raw CSVs are external data.
4. Follow `workflows/notion-mirror.md` to refresh the existing mapped mirror under the Ela Maayan Hub, including a source-commit permalink. If mirroring fails, retain the committed knowledge and report the stale mirror.
5. Update existing operational content-bank links/status as appropriate. Follow its publishing process, including `אפשר להעלות`. Saving a draft does not authorize publishing. Create no schedule unless requested.

## Conflicts and boundaries

Git wins for canonical knowledge. Reconcile direct mirror edits as proposed Git changes before refreshing them; preserve rationale. Do not create another knowledge tree outside the Ela Maayan Hub or reorganize unrelated existing pages.

References grant no extra access. State inaccessible sources precisely and continue independent work without guessing or changing sharing permissions. Use our own skills first; any future third-party adaptation needs its source, license and version recorded.
