# Working in the Ela Maayan content harness

Use this repository for carousels, brand work and Reels. Read `references/sources.json` first. Git is authoritative for reusable procedures, Notion for project knowledge and decisions, and Drive for production files and media.

## Start

1. Find the existing content item in the linked Notion content bank. Read its current brief, approved wording, feedback, status and linked files. For brand work, read the linked current brand knowledge and asset index.
2. Read the current knowledge home and relevant decision/source pages. Do not treat an archived performance snapshot or older research note as current data.
3. Match `skills/*/SKILL.md` by frontmatter name and read only the procedures needed. The catalog describes each role. Do not claim a skill was loaded unless it was read.
4. Read the pointer files accompanying the skill and fetch their Notion source. Original bundled photo previews and metric CSVs are deliberately not in this repository. Resolve media through the source registry in Notion and download to `.work/` or another temporary directory. Use the metric script with an actual temporary CSV path.
5. Follow the current user brief and current Notion decisions when they refine older imported defaults. In particular, a CTA is optional: story, humor, friendship or beauty can be complete outcomes. Never invent an action requirement because a template has that field.

## Produce and review

- Preserve approved copy character for character; change line breaks only when needed. Record requested wording changes in Notion.
- Select real photos and screenshots through Drive references. Do not fabricate product behavior, community quotes, platform facts or metrics.
- For carousels, review slides 1 and 2 independently and in sequence; inspect the whole payoff at phone size. Preserve Hebrew RTL and readable hierarchy.
- For brand work, read the current direction before refining it. Keep boards, assets, rationale and versions connected through Notion and Drive.
- Record owner preference, observation, platform statement, design principle and experiment as different evidence types. Do not turn a single successful post into a universal rule.
- For a small approved revision, apply the requested change and relevant checks without reopening the whole concept.

## Finish

1. Upload authorized production outputs to the existing Drive destination with a clear version name. Git stores their stable source IDs/URLs, not media bytes.
2. Update the Notion item with the chosen version, exact copy, meaningful changes, feedback, unresolved questions, next step and the harness commit used. Use `templates/session-handoff.md` when helpful.
3. Save project decisions, findings and performance in Notion. A reusable process improvement belongs in a narrowly scoped Git change with a Notion evidence link. Keep prior rationale in Notion when a decision is superseded.
4. Follow the existing publishing process, including the `אפשר להעלות` status. Preparing or saving content does not itself authorize publishing. Do not create schedules unless requested.
5. Inspect the staged files before a commit. Exclude media, raw datasets, private knowledge copies, downloaded files, account exports, secrets and expiring signed URLs. A `.gitignore` is a convenience, not proof of safe contents.

## Connections and failures

Use the available authorized Notion/Drive/Metricool tools. Connection configuration and credentials stay outside Git. If a source is inaccessible, state the exact missing source and continue independent work; do not guess its contents or broaden sharing permissions. References do not create an automatic sync.

Use our own skills first. Future third-party additions require an identified source, license and recorded version. No Tal/Travelers material is included in the initial import.
