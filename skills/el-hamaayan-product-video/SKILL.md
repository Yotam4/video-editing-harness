# El Hamaayan Product Video

Read the canonical harness at https://github.com/Yotam4/video-editing-harness through a checkout or connected GitHub tools. Load `docs/production/product-video-playbook.md`, current brand/voice knowledge and the selected registry recipe. Read `docs/research/video-harness-review.md` before using third-party methods. Do not claim Tal's unidentified source was imported.

## Establish the job and source

Classify the archetype, format/placement, audience situation and intended outcome separately. Use `el-hamaayan-social-brainstorm` if the concept is still open. Keep an approved revision narrow. A CTA is optional, and a milestone film can end with thanks rather than an install pitch.

Read the existing content record, current product facts, approved copy and available media. Inspect the actual authorized app flow: starting state, action, target and result. Code or a release note can locate a feature but does not prove user-facing availability. Ask only for consequential missing proof or assets.

Prefer real screen capture, then the actual rendered component. Clearly label a stylized reconstruction or schematic and derive labels/states from verified sources. Never fabricate UI, rollout, usage metrics, reviews or customer messages. For a forum demo, retain enough real forum context to explain how it works.

## Plan the film

Write one visual argument and a compact scene contract: viewer job, source/build/version, claim and proof/date, exact copy, action/result, timing/reading hold, purposeful motion, audio role and observable acceptance check.

Offer genuinely different treatments when requested. Make motion serve an action or relationship: context-to-detail crop, real tap indicator, focus highlight, shared element, caption reveal, verified counter or map sequence. Do not animate merely to look busy, impose fixed scene counts/durations, or let a beat cut off readable Hebrew.

Select the smallest adequate production tool. Use the existing `el-hamaayan-reel` for natural footage with simple overlays. Consult current official tooling docs before writing renderer code; no new renderer, package or music license is implied by this skill.

## Execute and inspect

When production is authorized, make a representative frame or rough sequence when it resolves uncertainty, then render the requested artifact. Review actual output: tap targets, dense UI, longest Hebrew line, mixed numbers, cuts, end state and independent cover. Inspect the whole video at phone size and check audio/captions through playback when available.

Verify technical metadata and accepted source/output versions. Distinguish still-frame checks, playback, audio review and metadata validation; never claim smooth motion or intelligible audio from a contact sheet alone. Preserve locked decisions and classify feedback as copy/timing, reskin, scene replacement or story rebuild.

## Save and learn

Save scene contracts, copy, proof, decisions, feedback and handoff in Git at `docs/content/<format>/<recipe-or-candidate>/<slug>/`. Save media, recordings and renders in Drive with stable source IDs/versions. Commit knowledge, then refresh its mirror only under the Ela Maayan Hub.

Choose available metrics for the job. Viewing or engagement does not establish product understanding, installs or activation. Record attribution limits and keep new product-video approaches labeled as experiments until supported.

This skill supplies a production procedure, not an installed renderer or automatic publishing. Report missing source access or unfinished checks precisely and complete independent work.
