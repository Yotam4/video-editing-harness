# El Hamaayan Brand Archive System

## Purpose
Use this skill whenever branding or logo work is created, refined, or reorganized.

The goal is to maintain a clean, decision-friendly archive instead of scattered files.

## Core principle
The archive must be easy to browse by:
- version
- flow
- asset type
- rationale
- decision history

Do not rely on ZIP files when the user wants normal browsing.

## Required folder structure
Use this logic unless the user explicitly asks for a different naming style.

- Brand & Logo Development
  - Master Index & Current Status
  - Versioned Logo Development
    - V1 — Original Sketches & Semantic Extraction
    - V2 — First Refined Exploration
    - V3 — Strengths & Weaknesses Refinement
    - V4 — [Name of round]
      - Flow 1 — Hidden Spring
      - Flow 2 — Route to the Spring
      - Flow 3 — Spring-Path Monogram
  - Future — Custom Font & Lettering
  - Future — Supporting Brand Assets

## Required contents inside each flow folder
Every flow folder must contain:
1. Full board file(s)
2. Individually extracted transparent PNG assets
3. Rationale / explanation page
4. What changed from previous version
5. Open questions / next refinements

If a flow has multiple sub-rounds, label them clearly rather than mixing them.

## Required file naming rules
Use names that encode version, flow, and asset type.

Examples:
- V4_Flow_2_01_Full_Board.png
- V4_Flow_2_02_Hero_Mark.png
- V4_Flow_2_03_App_Icon.png
- V4_Flow_2_Rationale
- V4_Flow_2_What_Changed

Prefer concise file names with predictable numbering.

## Asset extraction rules
When a board contains multiple useful marks or lockups, extract them as separate transparent PNG files.

Do not stop at uploading only the board.

Typical extracted asset set:
- hero mark
- app icon candidate
- primary lockup
- supporting variations
- pattern / texture asset
- badge / seal if present
- wordmark / alternate wordmark if present

## Master index requirements
Maintain a top-level index page or document that contains:
- current version overview
- what each flow means
- strongest current direction
- what changed in the latest round
- unresolved questions
- links to all version folders
- future tasks

## Version summary requirements
Each version should have a short summary covering:
- the goal of the round
- what improved
- what remained unresolved
- what the next round should focus on

## Future task handling
If a future idea appears during the work, preserve it in the archive instead of leaving it only in conversation.

Examples:
- custom font / lettering system
- icon system
- UI asset system
- signage / merch exploration
- Hebrew / Latin type expansion

## Browsing preference rules
If the goal is review or decision-making:
- prefer normal folders and individually visible files
- avoid ZIP-first organization
- keep rationale near the assets it explains
- separate V1, V2, V3, etc. clearly

## Consistency rules
Do not:
- mix assets from the wrong version into another version folder
- place V3 assets under V2
- leave ambiguous folder names
- use generic filenames like final.png or imagegen.png
- upload unrelated temporary artifacts into the archive

## Cleanup rules
If temporary upload tests or broken files are created:
- remove them
- correct the archive structure
- leave only the intentional browsing structure visible

## Final rule
The archive is part of the design process. If the files are not structured well, the design process is not finished.
