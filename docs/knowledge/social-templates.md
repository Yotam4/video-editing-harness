# Adaptation and versioning

## Preserve versus change

Preserve the approved reference's essential identity: real assets, recognizable visual family, original logo, intentional type hierarchy, and the owner's approved words. Adapt the crop, reading order, density, and screenshot scale to this story and target ratio.

Explain consequential changes by the viewer's need: “enlarge this screen so the relevant control can be read,” “move the headline into quiet sky to keep the gesture visible,” or “make slide 2 name the feature for someone entering there.” Do not justify changes with unmeasured claims about algorithm rewards or model-generated attention maps.

Keep current approved copy and source IDs in the working brief. Give review variants clear version names, for example `public-transport-f3-adapted-v01`. Record the family/version, original asset IDs, changed elements, and approval state. Never overwrite the original Drive master or move its files merely to organize a derivative.

## Evolution loop

1. Reuse the nearest suitable family and note one suspected weakness.
2. Change one meaningful variable for a comparable post when feasible.
3. Review the actual creative and matched-age outcomes through the engagement lab.
4. If the result repeats across relevant work, update the family's default with evidence and a date. If it does not, keep a variant rather than announcing a new universal rule.
5. Retain historical versions and lineage. Update the registry when a current source supersedes an older one; do not erase the old measured post's design context.

Do not create weekly tasks, publish content, or notify others merely because this process is reusable. The user can request a recurring review separately.

## Image-model use

Read the visual-design skill's reference-based brief guide. Supply reference roles explicitly, preserve real subjects, and request the smallest change. Keep final logo and UI as authentic source layers. Inspect Hebrew and every claimed documentary element after generation. An AI layout proposal is a proposal until visually reviewed; it is not automatically a new approved master.

## Creative/performance joins

Use three statuses:

- Exact: published asset/order/text verified against the source.
- Candidate: caption/date/topic and visible content are consistent, but the exact export is not verified.
- Reference only: useful appearance or historical source without a demonstrated published-performance join.

Keep missing creative visible. Do not call a contact sheet a complete inspection of all original-resolution text, or a sample-frame review an audio review.
